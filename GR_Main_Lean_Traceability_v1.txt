GR — Main manuscript to Lean traceability registry
=================================================

Purpose
-------
For every principal definition, lemma, proposition, theorem, imported
classification, and explicit physical/effective bridge used in the GR
manuscript, identify one Lean declaration (or a small public interface) that
serves as its manuscript-facing formal counterpart.

The registry is intentionally compact. Detailed semantic-fidelity judgments,
verification methods, configuration control, and scope exclusions are recorded
in `GR_Formal_Verification_Traceability_Matrix.md`.

A manuscript-facing interface should be recognizable beside the corresponding
main-text statement. Implementation helpers may sit below it, but the reader
should not have to reconstruct the conceptual claim from unrelated Lean
internals.

Status convention
-----------------
MATCH     = manuscript statement and Lean interface have been checked and agree.
ENCODING  = explicit semantic, representational, or physical bridge; its use is
            checked, while physical adequacy remains conceptual.
EXTERNAL  = imported standard mathematics represented by an explicit theorem
            interface; Lean checks application but does not re-prove it.
SCOPE     = manuscript interpretation or outlook deliberately outside the
            present GR Lean theorem layer.
CHECK     = plausible interface identified, but detailed comparison remains open.
GAP       = no adequate manuscript-facing Lean interface identified.
TODO      = interface identified, but dependency-report or manuscript cleanup
            remains open.

REGISTRY SUMMARY
================

The current GR Lean architecture intentionally contains four different kinds
of manuscript-facing object:

1. imported verified SBI/Time foundations;
2. explicit physical/effective semantic bridges;
3. imported standard mathematical classifications; and
4. derived conclusions checked by Lean.

Section-4 horizon, cosmological, energy, continuum-breakdown, and quantum-
gravity interpretations are tracked explicitly as scope items rather than
being allowed to appear as machine-verified consequences.

The authoritative machine-derived architecture is generated by
`GR/DependencyReport.lean`, `GR/RefinedGroupedReport.lean`, and
`GR/ColoredDependencyReport.lean`. The refined grouped map, not a separately
maintained hand-drawn graph, should be used for the manuscript dependency
figure.
